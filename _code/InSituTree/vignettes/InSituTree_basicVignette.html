InSituTree hierarchical cell typing

Claire Williams

2024-12-12

Overview

The InSituTree package is a small package that builds on InSituType and provides a specialized application for its use. With this approach, you can perform supervised cell typing in a hierarchical manner – first making broad cell type assignments and then making progressively finer classifications.

# Install from github

Optional inputs

The remaining inputs to InSituTree are optional, with some having default values.

  1. bg: Expected background, optional. Can be a value for each cell or one value for all cells. Typically expected to be left NULL to be automatically derived from the neg vector. Can be derived with the estimateBackground function from the InSituType package.
background <- NULL

## Not used, for demonstration
#bg_example <- c("c_3_18_2" = 0.00278, "c_3_18_3" = 0.00437", "c_3_18_4" = 0.01431 . . . )
  1. cohort: A vector of cohorts provides a grouping of cells based on alternative, non-RNA, data types, such as immunofluorescent staining, cell shape metrics, tissue structures, etc. One way to generate these cohorts is to use the fastCohorting() function in the InSituType package and include any variables that might be informative for cell typing, except variables you’ll want to analyze later. For example, if you’ll later perform differential expression as a function of spatial context, then it’s safer to exclude spatial context from the cell typing exercise (and therefore from this function). In this small example we will not use cohorts, but it is generally recommended. The random vector below is provided to give an example of the expected structure. See the InSituType package for more information about how to generate cohorts with the fastCohorting() function.
# These will not be used in this vignette and should not be random.

  1. excluded_genes: A character vector of genes to exclude from the cell typing. For example, these may be genes with a strong platform effect between the query dataset and reference profiles. Default is NULL.
genes_to_exclude <- c("MALAT1")

Value should be between 0 and 1; default is 0.5.
quantile_abs_difference <- 0.5

The only gene passing both of the above filters is JCHAIN, and so in this small example where we’re considering all cell types together and only six genes, only this gene would be considered as having high differentiating power at the given granularity level. Note that when fewer cell types or subtypes are considered simultaneously, we expect to see more variability in the diffs and percs.

  1. return_summary_annotation: A logical value indicating whether to return the final summary annotation. This data frame shows the annotation that has been made for each cell at each level of the annotation tree. Recommendation is to keep this at its default value of TRUE.

  x = counts,
  neg = negmean,
  bg = background,
  full_profiles = ioprofiles,
  cth = celltype_hierarchy_list,
  name_for_new_annotation = annotation_names,
  cohort = NULL,
  excluded_genes = genes_to_exclude,
  quantile_absolute_expression_difference_param = quantile_abs_difference,
  quantile_percent_expression_difference_param = quantile_perc_difference,
  return_summary_annotation = return_summary_df
)

Review results

The results from running InSituTree contain two main components:

  1. Nested list of results from each run of InSituTypeML

  2. Summary of annotations at each level of the tree

The nested results list contains the typical outputs of InSituType for each round of cell typing, and one additional metric, ctsPerCell, which is the counts of the selected genes for each cell at the given round of subclustering. This counts metric could be used to evaluate the confidence of a particular round of subclustering, since cell type assignments for low-count cells are likely to be less confident. Each level of the results list contains:

  • result: The InSituType results plus counts per cell for the current level of cell typing.

  • subclusterings: A nested list of clustering results for the next level down of annotations.

  • name: The node name of the current level of cell typing.

The summary annotation data frame shows the cell type assigned at each level of annotation, as well as the posterior probability for each assignment. Any final cell types, found as endpoints in the cell type hierarchy, are cascaded right to further annotation levels. For example, cells assigned to ‘endothelial’ at annotation level 2 in this example will also be labeled as ‘endothelial’ for annotation levels 3 and 4. In other words, the the right most annotLevel will contain the final cluster assignment at the finest level.

Note that any cells which did not have any counts in the genes used for subclustering will not get a cell type assignment; if this happens in the first round of annotation, these cells will show NA for all annotation levels. If this happens at later rounds of annotation, the last assignment will be cascaded right. One such example is shown in the results below
